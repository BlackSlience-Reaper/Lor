# 双版本适配

同一份源码分别构建 STS2 **0.107.1** 和 **0.111.0**，根目录的稳定加载器选择实现 DLL。三个模组各共享一份 PCK。发行版本为 LibraryOfRuina 0.22.7、ActLikeIt2 0.2.3、LibraryOfRuinaLib 1.3.2；RitsuLib 最低版本保持 0.6.2。

## 范围与前置结论

| 仓库 | 起点 | 本地分支 |
| --- | --- | --- |
| s1f102500012/LibraryOfRuina | `421987622d37cfb32d62f08a63b0c78cd8ccb485` | `dual-version-0.107.1-0.111.0` |
| BlackSlience-Reaper/ActLikeIt2 | `92ba4de2e6bfd386605a056900da0e6f8db9bd0a` | 同上 |
| Xuyuha/LibraryOfRuinaLib | `f9585913b231cca2072864825d36483052085737` | 同上 |

原 LibraryOfRuinaLib 1.3.1 不能直接用作 0.107.1 前置：用正确旧版引用编译时首先出现 19 个错误，涉及 CardLocation、伤害覆写、AfterBlockBroken、回合结束 Hook。1.3.0 源码也存在同类断点。随后按追加授权，把基础库也纳入双版本适配；没有把旧发行 DLL 当作已兼容。

前置检查还发现 MSBuild 的 `CandidateAssemblyFiles` 会优先拾取基础库 `libs/sts2.dll`，即使设置了旧版 HintPath 也可能假通过。三个工程均禁用该搜索来源；构建引用使用指定目标目录。ActLikeIt2 原源码的旧版编译最先报两处 FadeOut 错误，元数据扫描另外发现 `NBestiary.AddEvents` 在旧版不存在。

原 `Sts2Beta=false` 是混合历史分支，不能代表 0.107.1：大厅重连和 SavedPropertiesTypeCache 分支适用于旧版，但奖励遗物额外同步不适用。两个目标的 RelicReward.OnSelect 都依赖奖励集同步；重复发送获得遗物消息会破坏同步。因此移除含糊的开关，改用版本属性。基础库另有 5 个被 `STS2_BETA` 隐藏的覆写；两个目标原版均存在这些签名，现均正常编译其转发逻辑。

## 原版差异与处理

所有签名均以对应 `game-refs/sts2.dll` 为依据；编译通过后继续扫描 Harmony 字符串目标与注入参数，不能只修 CS0115。

| 原版变化 | 影响 | 处理方式 |
| --- | --- | --- |
| ModifyDamageAdditive / Multiplicative / Cap 的 CardPlay 参数 | 旧签名在新宿主上不能形成正确覆写 | 覆写签名按目标编译；基础库自定义伤害接口仍保留 CardPlay，旧版原版回调转发 null |
| AttackCommand.FromCard、CreatureCmd.Damage 增加 CardPlay | 方法体及 Harmony 重载目标均变化 | 两套 GameApi / CreatureCmdCompat；补丁目标声明按参数列表切换 |
| AfterBlockBroken 从 Creature 变为 context、target、breaker | 普通力量和多模式力量转发 | 覆写签名切换，基础库分部文件保留各目标的有效转发 |
| CreatureCmd.LoseBlock 增加上下文和移除者 | 多个战斗行为与验证夹具 | GameApi.LoseBlock 分部实现 |
| CardLocation 与旧 PileType/CardPilePosition 元组 | Iori 附魔、LibraryMultipleModePower、LibraryPowerMode | 各版本整个分部文件；保持手牌/牌堆位置选择 |
| CardPlay.Player 在旧版不存在；新版为 required init | 对出牌者的访问与验证工程造牌 | 旧版取 Card.Owner；夹具用分版本工厂，新版明确设置 Player |
| RunManager.FadeOut 旧版不存在 | ActLikeIt2 进入章节 | 旧版沿用原版 TestMode 判断和 Transition.RoomFadeOut；新版调用 FadeOut |
| NBestiary.AddEvents 旧版不存在 | ActLikeIt2 图鉴补丁在安装时失败 | 新版在 AddEvents 前追加；旧版在 CreateEntries 完成发现集初始化后追加 |
| Hook.BeforeSideTurnEnd / AfterSideTurnEnd 的旧名 | 回合开始结束相关补丁 | 声明切换为 BeforeTurnEnd / AfterTurnEnd；名称及参数已核对 |
| BeforeCombatRewardOffered 旧版不存在 | 嘉宾战追加奖励 | 旧版在原有奖励补丁里先生成全部奖励，再逐个追加和展示；新版调用原版 Hook |
| CombatManager.CurrentCombatId / CombatBegan 旧版不存在 | 战斗教学的延迟展示 | 用同一 CombatState 的引用校验；旧版逐帧等待启动阶段结束，新版保留事件触发 |
| SavedPropertiesTypeCache 只存在于旧版 | 自定义保存字段的网络编号 | 旧版显式注入并刷新位宽；新版由 ModelIdSerializationCache 管理，不再声称调用不存在的缓存类 |
| RunLobby.PlayerRejoined 的载荷和连接玩家集合不同 | 重连和剧情同步 | 分版本 RunLobbyEventsCompat |
| Rng 从 uint seed/counter 转为 ulong 和四段状态 | 遭遇序列、独立 RNG、验证夹具 | 旧版使用原生 seed/counter；新版保留原有四段状态 FNV 混合。均不消耗传入随机源 |
| CardModel.CreateDupe(Player) | 复制牌所有者 | 旧版 CreateDupe 后设置 Owner；新版传 Owner |
| DarkOrb.ActivateEvoke、HibernatePower 旧版不存在 | 激发通知和状态判断 | 旧版按原版无通知、无该力量处理；新版保留调用 |
| EventSynchronizer 的事件战斗重置 API 旧版不存在 | 嘉宾事件战斗切换 | 旧版没有该内部同步器；新版保留离开和重建调用 |
| NControllerManager 导航属性、MegaInput.confirm | 设置界面和验证输入 | 分别映射 IsUsingController / IsUsingDirectionalNavigation、accept / confirm |
| Mod.assembly 变为 assemblies，并新增 AssociateAssemblyWithMod | 模型发现、前置加载和模组归属 | 加载器按宿主接口关联实现；基础库的程序集枚举也按目标编译 |
| ModelDb.All、Rng.ToSerializable、每日词条生成入口 | 验证工程 | 按目标枚举已注册模型、读取计数和生成相同用途的夹具，没有删除验证项 |
| CardCreationOptions.CustomCardPool、CardPileCmd.Add 的 isChangingOwners | 已有卡牌选项与移牌兼容层 | 当前源码没有使用 CustomCardPool；原有 CardPileCmdCompat 已适配可选参数，两个目标编译通过，未另改玩法 |

除覆写签名和补丁声明外，版本差异位于整个文件被 `#if STS2_0_107_1` 或 `#if STS2_0_111_0` 包住的分部文件。已有通用反射兼容层继续保留，不扩展新的运行期版本猜测。

## 构建与引用

需要 .NET 9、Godot 4.5.1 .NET、两个版本的原版程序集，以及 RitsuLib 0.6.2 变体包。不要用 Godot 4.6 导出资源：游戏会拒绝较新格式的 PCK。打包脚本检查 PCK 文件头。

`CompatibilityTarget` 默认 `0.111.0`，只允许 `0.107.1` 和 `0.111.0`，其他值在构建前报错。一次切换同时决定：

- `GameRefsRoot/<目标>/game-refs`，包括 sts2、Harmony、GodotSharp；本机根目录默认 `~/sts2-mods/HextechRunes/versioned-dll-backups`。
- RitsuLib 的 `compat/<目标>` 与 shared；优先使用 `build/deps/STS2-RitsuLib-0.6.2`，否则使用工坊目录。可通过 `RitsuLibRoot` 指定根目录。
- `STS2_0_107_1` / `STS2_0_111_0` 编译常量、实现 DLL 的目标元数据、目标独立的 obj/bin。
- ActLikeIt2 的 `build/variants/<目标>/ActLikeIt2.dll` 与基础库的 `build/bin/LibraryLib/<目标>/Release/net9.0/LibraryOfRuinaLib.dll`。

在本体 `build/ActLikeIt2-src` 和 `build/LibraryOfRuinaLib` 准备两个前置的双版本分支。不要再用原上游未适配的 main，也不要引用发行根目录的加载器 DLL。`tools/build_lib.sh <目标>` 只构建当前检出，不会 fetch、checkout 或覆盖工程文件。

```bash
# 以下命令在本体仓库执行；也可给工程和脚本传绝对路径。
bash tools/build_lib.sh 0.107.1
dotnet build build/ActLikeIt2-src/ActLikeIt2.csproj -c Release -p:CompatibilityTarget=0.107.1
dotnet build LibraryOfRuina.csproj -c Release -p:CompatibilityTarget=0.107.1

# 另一个目标同样构建，不能只改清单复制一个 DLL。
bash tools/build_lib.sh 0.111.0
dotnet build build/ActLikeIt2-src/ActLikeIt2.csproj -c Release -p:CompatibilityTarget=0.111.0
dotnet build LibraryOfRuina.csproj -c Release -p:CompatibilityTarget=0.111.0

CompatibilityTarget=0.107.1 bash tools/check.sh
CompatibilityTarget=0.111.0 bash tools/check.sh
```

本体输出为 `build/bin/LibraryOfRuina/<目标>/<配置>/LibraryOfRuina.dll`；验证工程相应在 `build/bin/LibraryOfRuinaVerification/`。`check.sh` 需要 Python fonttools。加载器固定引用 0.107.1 的最小宿主接口，只编译一份，程序集身份是 `<模组 ID>.Loader`。

三个仓库各有 `tools/build_dual.py --pck <共享资源包> [--refs <版本引用根目录>]`。本体脚本先按目标构建当前的两个前置源码；前置各自的发行包仍需在各仓库单独生成。脚本只写 `build/dual-release/`，不会部署真实游戏目录。

本机工坊 RitsuLib 在工作期间为 0.6.5。为固定最低版本验证，使用 [官方 0.6.2 发行包](https://github.com/BAKAOLC/STS2-RitsuLib/releases/tag/v0.6.2)，ZIP SHA-256 为 `89188e58de017245605295459f5117c70100b6e51a356977ab24b1999ec82b1d`。两个原版 sts2.dll 的 SHA-256：

- 0.107.1：`e7ceb80669bfaf5c8fccabaa126ae2bb283aba514be5b5b55612579cfd285f18`
- 0.111.0：`9cb4f1ad8c9f284aa8fec3122ffd6d780bbf543d875c817abdd12ff63fbf12b4`

## 发行目录与加载顺序

```text
LibraryOfRuina/                         # 两个前置使用同样结构、换为各自 ID
├── LibraryOfRuina.json                 # min_game_version = 0.107.1
├── LibraryOfRuina.dll                  # 身份为 LibraryOfRuina.Loader
├── LibraryOfRuina.pck                  # 唯一共享资源包
├── libraryofruina-variants.manifest
├── bundle-evidence.json                # 源码提交、是否有改动、各文件 SHA-256
└── lib/
    ├── 0.107.1/
    │   ├── LibraryOfRuina.dll          # 身份仍为 LibraryOfRuina
    │   └── compat-target.txt
    └── 0.111.0/
        ├── LibraryOfRuina.dll
        └── compat-target.txt
```

加载器选择“不高于宿主的最新变体”，校验允许目标、路径、标记、SHA-256、程序集身份和目标元数据。未知宿主或没有合适变体时失败，不猜测目标。0.109 选择 0.107.1、未来版本选择 0.111.0 是选择规则，不代表额外版本已验证。

0.111.0 调用 `ModManager.AssociateAssemblyWithMod`，确认关联成功后才初始化；不安装类型发现桥接。0.107.1 等对应模组检测完成且状态为 Loaded 后改写 `Mod.assembly`，再初始化，避免被原版覆盖。同时给旧版 ModTypes 缓存追加当前实现类型并去重，保留之前的顺序。类型枚举不完整时失败，不能静默丢模型。

## 身份、数值与护栏证据

`tools/compare_dual.py` 对发行 DLL 做 Cecil 元数据解析，再用 Roslyn 分别预处理两个目标的源码。它不运行模组初始化或补丁目标解析方法。完整结果见 [双版本清单比对.json](双版本清单比对.json)。

| 模组 | 模型类型 | 自定义 SavedProperty | 补丁类 | 常量字段 | 两目标结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| LibraryOfRuina | 910 | 235（64 个声明类型） | 342 | 6555 | 完全一致 |
| ActLikeIt2 | 1 | 0 | 20 | 23 | 完全一致 |
| LibraryOfRuinaLib | 21 | 0 | 91 | 188 | 完全一致 |

保存字段比较包括声明次序、字段名、类型、SavedProperty 构造参数及命名参数；补丁 ID/所有者没有改名。与本体原基线比较，模型、SavedProperty、注册发现顺序不变。源码数值在所有玩法成员中一致；唯一不同项是 GameApi.CreateDetachedRng 中新版四段随机状态的 FNV 混合常数。这是原版随机状态表示适配，不是卡牌、怪物或奖励数值变化，也不承诺不同游戏版本生成相同随机序列。

`snapshots/<目标>/` 分别保存 type_order、discovery_order、static_fields、补丁声明等。本体 type_order 比原基线增加兼容工具 GameApi；有序注册清单不变。旧版额外有 SavedProperty 位宽刷新日志标志，新版有重连载荷适配委托；静态字段生命周期以公共登记表加目标补充表检查。补丁目标签名和说明随目标变化，因此不能共用整套快照。

原版拷贝守卫也拆成 `vanilla_copy_guard.<目标>.txt`，每个目标 82 个方法体。0.111.0 原版方法没有漂移；原表中的 12 项基础库指纹与当前源码构建不符，已检查源码差异并固定本次基础库构建。旧版的状态机编号、切边签名和伤害接口不同，使用对应程序集离线生成；新版离线结果与实际运行导出逐项一致。`check.sh` 会重新计算并比较，接受普通快照不能覆盖这项失败。

## 验证结果与边界

最终包的源码提交、文件哈希、隔离加载关键日志和两目标护栏日志摘要见 [双版本加载验证.json](双版本加载验证.json)。这份证据对应文档证据提交之前的实现提交；之后仅补充文档，不改变 DLL 源码。

- 三个实现均分别针对两个目标零错误编译；三个加载器零错误编译。仍有原有 nullable、异步等编译警告，未通过压制警告伪造“零警告”。
- 本体两目标 `tools/check.sh` 通过，包括 Debug/Release 构建、验证工程编译、1833 项 PlayerIntMap 检查、19 个 Harmony 类规则夹具、4 项 IL 指纹夹具、静态字段登记及目标快照。
- 六个实现 DLL 的静态 Harmony 目标和按名称注入参数均解析成功。动态目标类数为本体 29、ActLikeIt2 1、基础库 3；不把静态扫描冒充动态安装证明。
- 每个加载器通过 11 项离线检查：版本选择、低于最低版本、未知宿主、非法目录、非法目标、错误哈希、错误程序集文件名和目标标记。此检查不调用初始化。
- 0.111.0 使用 `cp -cR` 的 APFS 游戏克隆，独立 HOME，`--headless --force-steam=off`。仅安装 RitsuLib 0.6.2 与这三个包。日志确认三个 0.111.0 实现被选中并关联，初始化完成，本体 23 步完成、82 项原版拷贝指纹匹配。实际补丁表覆盖本体 342/342 类（395 个补丁方法记录）、ActLikeIt2 20/20 类（25 条）、基础库 91/91 类（100 条），没有缺项。
- 本体资源使用 Godot 4.5.1 重新导出；两个前置资源未修改，使用对应原发行 PCK。资源包在 0.111.0 成功挂载。未进行逐场景、逐贴图浏览。
- 隔离日志仍有 RitsuLib 0.6.2 对本机 `zh_hans_jp` 设置翻译资源的缺失提示、Steamworks.NET 镜像扫描跳过两个不可加载类型的提示、dummy 渲染器的空纹理提示，以及 Godot headless 退出时的资源回收提示；没有把这些日志写成“完全无错误日志”，也未据此证明实机纹理渲染正确。
- **0.107.1 未做运行时加载验证**。没有运行战斗场景套件、旧存档读写、重连或双客户端联机；跨游戏版本互联及存档互换也未验证。验证工程能编译不等于这些场景通过。

没有切换 Steam 分支，没有改动真实游戏目录、真实存档或云存档；仅管理本任务启动的隔离进程。交付为三个 PR，尚未合并、发布或上传工坊。基础库与章节框架的上游合并、版本发布顺序以及实机/双机验证仍由维护者决定。本体依赖两项前置 PR 的双版本产物。
