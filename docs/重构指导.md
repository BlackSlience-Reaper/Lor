# Library Of Ruina 重构指导

> 基准：v0.21.2 源码（本仓库 `src/`，1147 个 .cs、约 25 万行），游戏 v0.111.0。
> 对照：[模组设计哲学](模组设计哲学.md)（下文记作“哲学 §N”）；本地化相关见[四语本地化通用规范](四语本地化通用规范.md)。
> 证据等级：全部来自静态阅读与 `sts2-inspect` 对 0.111.0 原版的反编译；P0 条目逐条回到源码核对过行号。**没有构建修改版、没有 headless 运行、没有实机或联机测试**。标“待实机”的条目只确认了代码分支，没有确认玩家实际能触发。

## 0. 一页结论

1. **先止血，再重构。** 有 9 类问题会影响不玩本内容的玩家、其他模组或联机一致性（第 3 节）。其中大部分可以在**不改 SavedProperty 集合**的前提下修掉，应当单独发一个修复版。
2. **补丁层是最大的债。** 485 个 `[HarmonyPatch]`，跳过型前缀 88 个，11 个 Transpiler，19 个 Finalizer，没有补丁元数据，也没有统一应用器；同一原版目标按功能切成碎片（例如 `NTargetManager.StartTargeting` ×10）。需要一个统一应用器，再加 7 个 dispatcher。
3. **31k 行验证代码随正式版发布。** `src/debug/` 的 39 个验证补丁全挂在 `NMainMenu._Ready`，平时由命令行参数门控，不执行，但会编进 DLL、源码随 PCK 分发。应拆成独立的验证程序集。
4. **内容代码缺少中间层。** 8 个楼层解放遭遇战、34 个阶段 Boss、44 个书页遗物、40 个书页选项卡、102 个怪物各自手写同一套流程，估计可以去掉 1.5 万行以上的重复。
5. **联机不兼容的改动集中到一个版本做。** 改命名空间、删除挂在怪物/能力上的 SavedProperty、把设置迁进 run 级 Modifier，这三件都会让新旧版本无法联机。应当排到最后，一次做完，并在更新日志写明。

## 2. 动手前必须知道的约束

这些是“不改就不会坏、一改就会坏”的身份契约。每一步重构前后都要导出对照。

| 约束 | 原因 | 对照方法 |
| --- | --- | --- |
| **模型类名不能改** | 类名 slug 就是 `ModelDb` 的 `Id.Entry`，同时是本地化键、存档键、`MonsterVisualCatalog` 键 | 前后各导出 `ModelDb` 中本程序集的全部 ID 列表，diff 必须为空 |
| **命名空间前缀 `LibraryOfRuina` 必须保留** | `compat/SavedPropertiesTypeCacheCompat.cs:42-47` 按 `Namespace.StartsWith("LibraryOfRuina")` 过滤、按 `FullName` 排序；`:220` 把 `FullName` 写入 schema 指纹，指纹经 `MultiplayerConfigFingerprintPatch` 进入联机校验 | 改任何命名空间 = 与旧版无法联机，只能放在不兼容版本里做 |
| **SavedProperty 名字集合** | 集合决定 net-id 布局（哲学 §4） | 把“属性名 \| 类型”排序后落盘为快照，离线测试比对 |
| **`intentgraph.json` 里有 2 个类型全名键** | `features/intentgraph/IntentGraphConfigRepository.cs:26` 按类型全名取值 | 移动这两个类型时同步改配置 |
| **配置键名** | 玩家本地 `mod_configs/LibraryOfRuina.cfg` 按属性名存储 | 重命名设置属性 = 老玩家设置丢失 |
| **补丁执行顺序** | 同目标、同优先级的补丁按程序集元数据中的类型顺序执行；移动文件可能改变顺序 | 先导出现有补丁表（目标、种类、优先级、实际顺序），重构后比对（哲学 §8） |

## 3. P0：先止血（影响不玩本内容的玩家、其他模组或联机）

除 3.8 外，本节修复都**不改 SavedProperty 集合**。建议合成一个修复版先发出去。

### 3.1 残响乐团幕发布了“临时预览” godmode

- 证据：`src/patches/ReverberationEnsembleEntryPatches.cs:18-25`，`RunManager.EnterRoomInternal` 前缀每次进房间都调用 `ReverberationEnsemblePreviewGodMode.Update`。`:40` 注释写着“临时预览补丁：进入残响乐团幕后，为每位玩家启用原版 godmode 命令”，`:42-107` 对每个玩家执行 `new GodModeConsoleCmd().Process(player)`。
- 该幕在 `src/acts/LibraryActIntegration.cs:34-40` 无条件注册为第 4 幕，没有实验开关。
- 后果：
  - 原版 `GodModeConsoleCmd` 只在 `LocalContext.GetMe(...) == _godModePlayer` 时施加 999999999 的力量、缓冲、再生，所以联机时每一端只给自己上能力，第一场战斗起校验和必然分叉。
  - 施加走命令队列之外的 fire-and-forget。
  - 静态 `Dictionary<Player, …>` 在 `!RunManager.IsInProgress` 时不清理，`CombatSetUp` 订阅跨局残留。
- 做法：删除整个 `ReverberationEnsemblePreviewGodMode`。确实需要预览时，放进验证程序集（4.2），由控制台手动开启。该幕是否默认开放，由作者决定是否挂到 `ExperimentalContentEnabled` 之后。
- 待实机：普通流程通关第三幕后是否一定出现该幕选项（按 ActLikeIt2 的逻辑应当会出现）。

### 3.2 CombatSafetyNet：全局吞异常并单边修改战斗状态

- 证据：
  - `src/patches/CombatSafetyNetPatches.cs:23-31` 用跳过型前缀替换整个 `TaskHelper.RunSafely`。
  - `:33-58` 通过 `TargetMethods` 给 `Hook` 里所有返回 `Task` 的方法挂后缀包装。
  - `:60-231` 还包装了 `GameAction.Execute`、`ActionExecutor.ExecuteActions`、`StartCombatInternal`、`CheckWinCondition`、`Creature.TakeTurn`、`MonsterModel.PerformMove`、`AttackCommand.Execute`；`:233/:248` 在 `Hook.AfterDamageGiven/AfterAttack` 上有跳过型前缀。
  - `combat/CombatSafetyNet.cs:622` 的 `ShouldSuppress` 只排除取消异常、只要求处于战斗上下文，**任何模组的异常都会被吞掉**。之后 `RecoverAsync`（`:555-620`）会反射改 `_isPerformingMove`、推进怪物状态机、`RemoveCreature`、强制解除 `CombatManager`/`ActionExecutor` 暂停、重跑胜负判定。
- 违反：哲学 §2 全局兜底吞异常、`Hook.*` 总线；§4 共享状态只在对称路径改动。
- 后果：只在抛异常的那一端执行“修复”，把一次异常放大成永久分叉；第三方模组的真实故障被伪装成成功。源码注释（`CombatSafetyNet.cs:626-632`）自己也承认会固化分叉。
- 做法：
  1. 删除 `RunSafely` 替换、`Hook` 全量包装、`GameAction`/`ActionExecutor`/回合/招式包装、两个 `Hook.*` 跳过型前缀。
  2. 唯一真实注册的守卫 `GALAXY_CHILD_DOUBLE_FAKE_DEATH`（`CombatSafetyNet.cs:90-102`）改由 `GalaxyFriend` 自己的回合或死亡回调处理。
  3. 确实要保留保护的，只在本模组 `MonsterModel.PerformMove` 覆写里 try/catch，过滤器限定为本程序集对象，其余一律 rethrow；联机中出现异常只记日志，不做状态修复。
- 风险：以前被掩盖的崩溃会暴露出来。建议过渡一个版本，保留只读诊断日志。

### 3.3 运行时改写 net-id 表、在校验和前改状态

- 证据：
  - `patches/CombatSafetyNetPatches.cs:269-276`：`SavedProperties.WritePropertyName` 前缀调用 `CombatSafetyNet.RegisterSavedPropertyNameIfMissing`（`combat/CombatSafetyNet.cs:1500-1534`），运行期往 `ModelIdSerializationCache` 追加属性名并改写 `PropertyIdBitSize`（用 `Mathf.Log` 浮点计算）。只有碰到未知属性名的那一端会扩表，两端位宽从此不同。
  - `:287-296`：`ChecksumTracker.GenerateChecksum` 前缀在生成校验和之前移除“卡死的死亡敌人”（`CombatSafetyNet.cs:255-315`），把真实分叉掩盖成一致。
  - `compat/SavedPropertiesTypeCacheCompat.cs:296-306`：`InjectTypeIntoCache` 后缀在**每个模组**注入时重算全局 `NetIdBitSize`（非 Beta 分支）。
  - `patches/ModelIdSerializationCacheDuplicateWarningPatch.cs:43-93`：扫 IL 找 net-id 排序比较器，用跳过型前缀改它的返回值，只为压掉一条 “share an ID” 警告。
- 违反：哲学 §2 联机通道、SavedProperty net-id 表、拦日志压假警告。这正是工作区已知的联机分叉根因类型。
- 做法：前两个补丁和重复 ID 警告补丁直接删除；卸载模组后遗留的属性名，在读档时剔除，不在序列化时扩表；重复的 model id 修根因。`InjectTypeIntoCache` 后缀删除，只在 `InjectModSavedPropertyTypes()` 之后刷新一次（如果非 Beta 分支仍然维护的话，见 4.7）。

### 3.4 扫描第三方程序集并在运行期打 Transpiler

- 证据：`src/patches/LittleRedMercenary/FocusOfAttentionTargetPatches.cs:200-252`。
  - 在 `CombatManager.SetUpCombat` 前缀里运行期再 `new Harmony(...)`，遍历 `AppDomain` 所有非系统程序集（即其他模组），把每个 `Rng.NextItem<Creature>` 调用点转写掉。`Patch` 没有 try，抛异常会打断战斗初始化；`_applied` 在调用前就置 true。
  - 替换函数 `ChooseFocusedTargetAfterRngRoll`（`:53-67`）**即使场上没有“集火”也会先过滤存活和可命中再掷随机数**，改变了原版卡牌、法球和第三方随机选敌的分布，并剔除调用方有意包含的对象。
  - `:77-198` 另有 5 个针对原版 async `MoveNext` 的 Transpiler，`:335` 在 `DarkOrb.Evoke` 上有跳过型前缀。
- 违反：哲学 §2 其他模组的类型、§1 Transpiler 默认不用。
- 做法：删除外部扫描（第三方随机选敌不响应集火，写进说明）；替换函数在 `GetFocusedTarget == null` 时对原候选列表原样调用 `rng.NextItem`，保证零漂移；原版目标尽量收窄到 `AttackCommand.GetPossibleTargets` 这类入口；保留的 Transpiler 进原版拷贝守卫。
- 玩法变化：修正原版随机选敌，要进更新日志。

### 3.7 表现层先于同步写入，且没有 catch

共约 20 处，共同形态是：`await 视频/转场/动画/节点查找` → 然后才写状态，触发标志又在 await 之前已经置位。表现层在某一端抛异常，那一端的状态写入就被跳过，形成永久分叉（哲学 §4“表现层不能先于同步写入抛异常”）。

| 位置 | 形态 |
| --- | --- |
| `monsters/QueenOfHatred/QueenOfHatred.cs:424-446` | 先 await 反转视频（只有 finally 没有 catch），再写 `_isSnakeForm`、选目标、`SetMoveImmediate`、`PowerCmd.Remove`；调用方已先置 `TransitionTriggered=true`；等待后不复查存活 |
| `monsters/QueenOfHatred/QueenOfHatred.cs:895-896` | 先等本地音频播完（兜底 30 秒）才结算伤害 |
| `monsters/LanguageFloorLiberation/LanguageFloorMimicry.cs:948, 1074-1087` | 变身动画、告别动画排在 Form、属性、伤害之前；`_isTransitioning` 不在 finally |
| `encounters/LanguageFloorLiberation/LanguageFloorLiberationEncounter.cs` 第二到五阶段生成（678/685/701、744/751/767、802/809/837、890/897/913） | `CreatureCmd.Add` 在揭幕动画回调里；`TransitionPending=false` 在动画之后 |
| `monsters/KingOfGreed/KingOfGreed.cs:713-730` | 形态切换与月字排在能力增删之前；`_transformPending` 无 finally |
| `specialguests/Rnfmabj/RnfmabjMonsters.cs:893, 1061-1071, 1251` | `TriggerAnim("Split")`、`RefreshPlanDisplay()` 排在状态写入之前 |
| `specialguests/Iori/IoriMonsters.cs:1396/1414` | 格挡动画排在逃跑、快照写入之前 |
| `monsters/PhilosophyFloorLiberation/PhilosophyFloorTwilight.cs:386, 468, 491, 303-309` | 蛋状态表现排在 base 调用和扣血之前；钩子里 `await Task.WhenAll(演出)` |

做法：新增 `Presentation.RunSafe(Func<Task>, bool await)`，内部 try/catch 只记日志；所有调用点改为“先写状态、再调表现”；触发标志放进 try/finally，或在状态真正完成后再置位。

### 3.8 本地设置直接驱动玩法，且能在局中切换

- `MonsterExtensionEnabled` 控制遭遇池、事件池、遗物池与特殊来宾流程（`patches/LibraryEncounterWeightPatch.cs:187` 等 30 余处），**不在联机指纹里**；它的 setter（`features/settings/LibraryOfRuinaSettings.cs:125-154`）在局中关闭时会调用 `RestoreVanillaEncounters(...)`，本地重写当前局的房间序列。
- `ResistanceMode` 的 setter（`:101-115`）立即改写静态 `LibraryResistanceModeState.Current`，局中切换会让双端伤害计算不同。
- 做法：
  - 短期（不改属性集合）：局内把相关设置置灰；把 `MonsterExtensionEnabled` 加进指纹诊断。注意：改指纹字符串也会导致与 0.21.2 无法联机。
  - 长期：开局时把这些值写进 run 级 Modifier（房主决定，随存档同步），局内只读 Modifier，同时撤掉 `ModManager.GetGameplayRelevantModNameList` 指纹补丁（哲学 §2）。这一步会改属性集合，放进不兼容版本。

### 3.9 规范模型上读取实例状态

原版 `CardModel/RelicModel/PowerModel.Owner` 的 getter 第一行就是 `AssertMutable()`，所以 `Owner?.X` 在规范模型上同样会抛。卡牌、遗物、附魔的 getter 是干净的；问题全在 Power，共 **12 处 / 9 个文件**：

| 类别 | 位置 |
| --- | --- |
| `DisplayAmount` 覆写 | `powers/PunishingBird/PunishingBirdPunishPower.cs:41`；`powers/TechnologyFloorLiberation/TechnologyFloorRegretPowers.cs:92`（经 `:79`）与 `:290`；`powers/NaturalFloorLiberation/NaturalFloorNihilPowers.cs:187` 与 `:294`；`specialguests/Rnfmabj/RnfmabjPowers.cs:196` |
| 自定义 `DynamicVar.GetBaseValueForIConvertible` | `powers/LittleRedMercenary/LittleRedMercenaryPowers.cs:473, 508`；`powers/RedMist/RedMistPowers.cs:57`；`powers/WrathServant/WrathServantPowers.cs:350`；`powers/FairyFestival/FairyFestivalPowers.cs:135`；`patches/MultiplayerScalingReductionPatch.cs:126`（`ScaledMonsterHealVar`，被 5 处复用） |

做法：`LibraryOfRuinaPowerModel` 加 `protected bool TryGetOwner(out Creature owner)`（内部判 `IsMutable`）；新增 `OwnerScopedVar<TModel> : DynamicVar`，规范模型上回退到 `base.GetBaseValueForIConvertible()`。可以照抄已有的正确写法：`PhilosophyFloorTwilightPowers.cs:155, 231`、`PunishingBirdPunishPower.cs:25` 的 `{ IsMutable: true }` 模式匹配。另加一道静态检查，见第 7 节。

## 4. P1：结构重构

### 4.1 补丁层

**现状**

### 4.2 debug 层拆成独立程序集

- 现状：
  - 39 个 `*VerificationPatch` 都是 `NMainMenu._Ready` 的后缀，门控为 `CommandLineHelper.HasArg("lor-verify-xxx")`。普通玩家不会执行，但它们编进发行 DLL；同一目标重建 43 次替换方法；任一验证类打补丁失败，初始化日志会报“N 个补丁类失败”，把测试代码的问题当成模组故障。
  - 正式逻辑里有测试分支：`features/temporarymaps/TemporaryMapSessionManager.cs:263` 带 `lor-verify-` 参数时跳过 `SessionStore.ClearForRunStarted`。
  - 正式代码里约 30 个 `internal static Debug*` 访问器只为测试存在，例如 `monsters/LiteratureFloorLiberation/LiteratureFloorBloodlustBoss.cs:106-121`。
  - 验证代码已经过期：`debug/CodeHealthVerificationPatch.cs:82-99` 要求指纹包含 `+compat./+dll./+schema./+cfg.`，现行指纹只输出 `+设置.抗性…`；`debug/SocialFloorLiberationVerificationPatch.cs:2721-2731` 同时要求一个类型“被发现”和“不在同一集合中”。这说明这批验证没有定期执行。
  - 源码里有作者本机路径：`debug/LiteratureFloorLiberationPhaseOneVerificationPatch.cs:59, 1318`，Phase2–5 的 `:50/59`（`D:\sls2-resource\…`、`C:\Users\…\OneDrive\图片\sls2`）。
- 做法：
  1. 主 csproj 加 `<Compile Remove="src/debug/**" />`；发行改用 Release 配置。
  2. 新建 `LibraryOfRuina.Verification.csproj`（独立 manifest、依赖主模组，只在 headless 验证时部署）；主程序集加 `InternalsVisibleTo`，`Debug*` 访问器改为私有加测试可见。
  3. 一个 `VerificationRunner` 补丁取代 39 个，解析 `--lor-verify=<suite>[,<suite>]` 分派；公共部分抽成 `VerifyHarness`：`Require`、`WaitUntil`、`StartFakeRun`、`Finish(exitCode)`，以及私有成员反射表。现在 39 个文件各自实现 `_started`、参数判断、`Quit`，`Require` 35 份、`WaitUntil` 29 份、`EnterRoomDebug` 30 份。
  4. 纯数据契约（数值、loc 键、资源存在、配置结构）搬到不依赖 Godot 的 xUnit 工程；素材 SHA 对照搬到资源流水线脚本；本机路径改为环境变量或 `local.props` 注入。
  5. 只有“可选补丁目标解析”“SavedProperty 进指纹”“资源缺失”三项值得留作运行时诊断，改为启动摘要里的一行日志，不退出进程。
  6. `TemporaryMapSessionManager.cs:263` 的测试分支改为由验证程序集通过注入点控制。
- 控制台命令：`skip`、`multifight`、`multievent`、`tempmap` 都是原版默认 `DebugOnly`，普通玩家看不到，联机走 `ConsoleCmdGameAction`，确定性没有问题。但 `skip` 命名太通用，会与其他模组同名命令互相覆盖，应加 `lor_` 前缀；后三个迁入验证程序集。

### 4.3 初始化
